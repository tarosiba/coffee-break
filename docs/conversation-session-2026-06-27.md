## Cursor / 開発フローに関する Q&A

### `main` マージするかしないか

| | `main` にマージ | マージしない |
|--|----------------|-------------|
| 公開サイト | 数分で更新される | 更新されない |
| ユーザー | ホーム画面の PWA から遊べる | 古い版のまま |
| 中身 | アプリのプログラムだけが配信される | 個人データはどちらも端末内 |

### プライバシー（公開 URL）

- Coffee Break の予定・ニックネーム等は **端末の localStorage のみ**
- サーバーへの送信や、GitHub 公開による個人データの露出は **ない**
- カレンダーのスクショをチャットで送った場合も、**リポジトリや公開 URL には載せない**

### Web 版 Cursor のコンテキスト使用率

- デスクトップのような **円グラフ UI は Web 版には基本的にない**
- 目安: モデル上限（多くは約 200k トークン）、会話の長さ（6〜8往復〜）、要約表示・品質低下
- `cursor.com/dashboard/usage` の使用量は **課金用** で、コンテキスト満杯度とは別物

## ComfyUI 動画生成（自分の PC）

### 必要スペック（目安）

| レベル | GPU VRAM | 用途 |
|--------|----------|------|
| 最低限 | 8GB | 480p・短尺・Wan 1.3B |
| 現実的 | 12GB | 480p 安定運用 |
| 快適 | 16〜24GB | 720p・Wan 14B（最適化） |

- **RAM:** 32GB 以上（64GB 推奨、T5 オフロード時）
- **SSD:** 1TB 以上 NVMe（モデルが巨大）

### システム構築の流れ

```text
ComfyUI 本体（Portable または Desktop）
  → ComfyUI Manager
  → 動画用ノード（WanVideoWrapper、VideoHelperSuite 等）
  → モデル配置（models/diffusion_models 等）
  → ワークフロー JSON を読み込み
  → 480p・短尺でテスト
```

### 難易度の感触

- **プログラミングより易しいが、面倒なことはある**
- つまずきやすい点: モデルの置き場所、VRAM 不足、用語、ダウンロード時間
- 入門は **Wan 2.1 の 1.3B・480p** からが無難
